# nf-core module lint of the local modules

`nf-core modules lint --all --local` (nf-core/tools 4.1.0) is clean for the local modules except for the warnings below.
Each of them cannot pass for a reason outside the module code.
Source lines are from `nf_core/modules/lint/` of nf-core/tools 4.1.0.

| Test                            | Modules                                                                                                                 | Why it cannot pass                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docker_tag`, `singularity_tag` | 35 FragPipe, Philosopher and Python-helper modules (every module whose process has no `container` directive of its own) | The licensed FragPipe image is a runtime parameter only (`--fragpipe_container` sets `process.container`). The test resolves the container with `nextflow inspect -profile docker/singularity` (`main_nf.py:481-482`) and fails when none is configured (`main_nf.py:516`, `main_nf.py:520`). Nothing in the repository may name the licensed image.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `environment_yml_exists`        | 34 of those modules, plus `tdf2mzml`                                                                                    | Those tools have no conda package: FragPipe is a licensed distribution and the TDF converter has neither a Bioconda recipe nor a PyPI package. The test warns when a module has no `environment.yml` and no Dockerfile (`environment_yml.py:108-116`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `bioconda_version`              | `msstatslfq`, `mzmlindexing`, `openmspeakpicker`, `pmultiqc`                                                            | The test asks api.anaconda.org for the package and version, and warns "Conda version not specified correctly" whenever that request fails (`environment_yml.py:326-340`: a `LookupError` from `nf_core/utils.py:787-789`, "Could not connect to Anaconda API"), so on a host without access to api.anaconda.org it warns for any pin. The pins are correct: each exact version is in the Bioconda channel index (`repodata.json` read through the prefix.dev mirror on 2026-10-11): `linux-64/bioconductor-msstats-4.14.0-r44he5774e6_0.tar.bz2`, `linux-64/openms-3.5.0-h78fb946_0.conda` (the build the containers use, plus three other 3.5.0 builds), `noarch/pmultiqc-0.0.39-pyhdfd78af_0.conda`; the BioContainers images' `conda-meta` records the same packages from Bioconda's build. The warning clears on a runner with access to api.anaconda.org. |

The module directories and process names follow the lint's naming rule: a local module is named by its last directory (`nfcore_component.py:97`), which must be alphanumeric (`main_nf.py:342`) and equal the lower-cased process name (`main_nf.py:587`).
So `modules/local/checkcentroid` holds `process CHECKCENTROID`, `modules/local/philosopherfilter` holds `PHILOSOPHERFILTER`, and `modules/local/tmtlabelcheckanalyze` holds `TMTLABELCHECKANALYZE`.
The names are the former ones with the underscores removed.

Modules on the Seqera community registry (`iq` and the Python-helper modules) carry a `containers:` section in `meta.yml` (`meta_yml.py:364-389`, `module_containers.py`).
It names the images `main.nf` uses, with their Wave build and scan IDs and the conda lock file of the Docker build, all read from the Wave API (`https://wave.seqera.io/v1alpha1/builds/<build_id>` and `.../condalock`); the Singularity entry is the SIF artifact whose layer is the blob `main.nf` downloads.
No image was rebuilt.
